# 第 3 期验收｜单张 H100 上的 32B 教师与 8B 学生

2026-11-21 在 `hkust-gz-hpc3` 完成探测，运行 ID 为 `v2-phase3-20261121`。32B 教师生成了可供 8B 训练的四角色示范。全参数 SFT 和 LoRA-SFT 都完成了真实参数更新和学生重评。原版 8B 可进入第 4 期，LoRA 蒸馏继续作为正式实验的唯一 Optional。第 3 期仅使用 Phase 2 的 16 人 pilot 区块。正式样本规模固定为校准 128 人、测试 256 人。[分期协议](../../../global_guide/v2_frozen/phase3_pilot_budget.md) · [自动核查结果](pilot/audit.json)

## 三条路线需要多长时间

假设服务器已有两份模型快照和第 2 期名单，使用同一张卡串行执行。时间范围来自此次典型与长窗口的观测速率，适用于表中的工作量。CPU 聚合与评测采用固定规模合成数组计时，假设纯 CPU 作业期间释放 GPU。因此墙钟小时和 GPU 小时保留两位小数后相同。正式作业排队、首次传权重和本期探测单列。[估算 CSV](pilot/runtime_estimates.csv) · [分项秒数及速率](pilot/hardware.json) · [CPU 计时](pilot/cpu.json)

| 独立路线 | 预计墙钟小时（观测范围） | 预计 GPU 小时（观测范围） | 中心估计的组成 |
|---|---:|---:|---|
| 主 pipeline | 5.02（4.31–6.43） | 5.02（4.31–6.43） | 原版 8B 四角色 12,288 窗、单评审 2,048 窗、CPU 汇总 |
| 主 pipeline + SFT（全参数） | 11.48（9.53–13.49） | 11.48（9.53–13.49） | 主线 + 教师 1.72 h + 全参训练 0.05 h + 学生重评 4.70 h + 切换等开销 |
| 主 pipeline + SFT + LoRA | 13.53（11.45–15.70） | 13.53（11.45–15.70） | 主线 + 教师 1.72 h + LoRA 训练 0.13 h + 学生重评 6.63 h + 切换等开销 |

- 两条扩展均按教师上界 2,048 次生成计。首批 pilot 保留率为 4/32（12.5%），据此外推 256 条示范，batch 1 训练一轮。两条路线各自从原版 8B 启动。第三条直接用 LoRA 做 SFT。学生均需重评 12,288 窗，复用原版 B1。
- 如果保留率为 50%，在相同中位速率下，全参数路线约 11.62 h，LoRA 路线约 13.93 h。正式训练用户能构成的窗口数和教师保留率将在第 7 期得到实数。窗口成本先按角色计算每逻辑窗中位秒数，再对角色等权，范围用各角色观测到的最快和最慢值外推。装载、预热、保存及模型切换等固定开销由作业起止时间扣除已单计的工作量与压力测试得到。[估算实现](../../../code/phase3_estimate.py)
- 此次 LoRA 路线多出的约 2.05 h 中，约 1.93 h 来自学生重评。此配置推理时加载单独的适配器。训练样本少、学生生成长度和后端实现均会影响速率，正式模型的耗时可能超出观测范围。Phase 4–8 的排序效果仍待评测。
