### 2.2 生成固定名单

1. 采用 NFKC 归一化、英文转小写、折叠连续空白。BM25 查询由当前行业、当前岗位、学历、经历、期望行业和期望岗位类型组成。岗位文档由标题、岗位类型、关键词、最低学历及描述组成。字段内连续汉字取相邻二元组，英文抽取 `[a-z]+`，词项不跨字段。
2. 用全部有效 JD 的文本统计 IDF 和平均文档长度，冻结 BM25 的 `k1=1.2`、`b=0.75`，使用 `ln(1+(N−df+0.5)/(df+0.5))`。对查询的不同词项各计一次。每人只在其已浏览或投递过的岗位内选前 10，分数相同按 `jd_no` 升序。选榜不读取 `satisfied`，不按正例数筛人。保存完整有序 ID 与名单哈希。
3. 评审读取规范化的候选人履历、显式求职意向及窗口内 JD。保留对应的意向城市、岗位类型、薪资和学历等字段，匿名编码按原值呈现，缺失留空。原始人岗 ID 只用于关联，窗口中使用临时岗位编号。对模型隐藏三个行为标记、交互次数、标签、BM25 分数及其他评审意见。

## 3. 从四份评审到最终排名

### 3.1 评审与滑窗

四角色和综合评审均使用 `Qwen/Qwen3-8B`。角色提示分别要求 Skill 核对技能证据、Trajectory 分析经历与岗位跨度、Preference 核对显式意向、Employer 核对岗位门槛。综合评审一次综合考虑上述因素。每个窗口都要求按共同事件 `J` 的可能性从高到低排列 4 岗，并为每岗返回 `pJ`。Preference 另报 `pC=P(D=1)`，Employer 另报“假设已投递”时的 `pE=P(S=1 给定 D=1)`。两侧概率都以入池为条件。

统一使用非思考模式和贪心解码。每窗输入上限 3,840 token，输出上限 256 token，只输出排序和分数。按模型分词器计数，用户资料最多 512 token，每个岗位最多 640 token，结构化字段置于自由文本之前。截断保留前缀。模板保留角色指令和四个岗位编号，各方法使用相同文本与截断规则。在 pilot 记录实际 token 数和截断比例。

每位评审从同一 BM25 榜开始。按当前位置 **7–10 → 5–8 → 3–6 → 1–4** 依次写回局部排序。第二遍从更新后的榜尾开始，重复四个窗口。不同角色各自更新列表。输出为每角色一份 10 岗完整排名和逐岗位预测。概率先截到 `[0.0001,0.9999]`，对同角色、同用户、同岗位、同预测头的历次 logit 取均值，再用 sigmoid 还原。相关估计和 Brier 每岗只计一次。双遍滑窗源自 [ConFit v3 附录 G](https://arxiv.org/pdf/2605.09760#page=11)。

### 3.2 校准与共同错误

- **概率。** 在 C 内按用户散列顺序轮流分入三折。对每个角色的 `pJ`，在两折上最小化二元负对数似然拟合一个温度 `T∈[0.05,20]`，对余下一折计算 `sigmoid(logit(pJ)/T)`。轮换得到所有样本外预测。测试时的温度由完整 C 拟合。Preference 的 `pC` 用 D 校准，Employer 的 `pE` 仅用已投递的 S 校准。单类校准样本保留 `T=1` 并标记。无可用记录的预测头记缺失。
- **可靠度。** 每人取 10 个岗位的样本外 `(pJ校准−J)²` 均值，再对有完整选票的人取均值，得角色 `BSₐ`。令 `rₐ=exp(−BSₐ/0.25)`。只用共同事件计算四角色的可靠度。
- **共同错误。** 每对角色在人岗对齐的样本外记录上计算残差 `eₐ=pJ校准−J`。分别在 `J=0` 与 `J=1` 内求 Pearson 相关 `ρ₀` 和 `ρ₁`，取 `ρₐᵦ=(ρ₀+ρ₁)/2`。分层可减轻共享标签造成的表面相关。某层可配对记录不足两条或残差为常量时，该层项取 0 并注明原因。报告全部 6 对系数、各层样本量及正负方向。

### 3.3 聚合与双边重排

设 `sₐ(j)=(10−rankₐ(j))/9`。B1 直接返回综合评审顺序。B4 按有效角色的 `sₐ(j)` 等权平均。移除角色时在剩余角色上重新等权平均。T0 的未归一权重为 `rₐ`，T1 为

`w原始ₐ = rₐ / [1 + Σᵦ≠ₐ max(0,ρₐᵦ)]`。

相关惩罚由 C 的四角色一次算定。对当前查询中同时具有完整选票和可用可靠度的角色，将相应权重重新归一到和为 1。对该查询的每份完整排列 `πₐ`，PL 依次在剩余岗位中选择下一名。给 10 个岗位拟合分数 `θ`，最大化

`Σₐ wₐ Σₖ₌₁⁹ [θ(πₐₖ) − log Σₗ₌ₖ¹⁰ exp(θ(πₐₗ))] − 0.1 Σⱼ θⱼ²`。

T0、T1 分别按相应解降序排列。W1 使用和 T1 完全相同的角色与权重，按 `Σₐ wₐ sₐ(j)` 排列。两者比较时，变化只来自汇总排名的方式。所有分数平票按岗位 ID 升序。

令 `R(j)=(10−rank_T1(j))/9`，使用已校准的两侧概率生成最终榜单。

**`F(j) = 0.5 × R(j) + 0.5 × √(pC(j) × pE(j))`。**

按 F 降序推荐前 5 个岗位，同时保存完整 10 岗顺序、可信名次、两侧概率和最终分数。系数在测试前固定。

## 4. 结果评测与解释

每位求职者独立计分，再对该指标的可评价用户等权平均。位置折扣为 `1/log₂(k+1)`，二元标签直接作 gain。理想顺序由同一池内标签降序得到。所有方法共享每项指标的分母。

| 指标 | 评价名单与计算方式 | 用户分母 |
|---|---|---|
| **联合 nDCG@5（主指标）** | 原 10 岗按方法排序，以 J 计算前 5 的 DCG/理想 DCG | 池中至少一个 J 正例 |
| 联合 Recall@5 | 前 5 的 J 正例数 / 10 岗全部 J 正例数 | 同主指标 |
| 投递 nDCG@5 | 原 10 岗以 D 作标签 | 池中至少一个已投递岗位 |
| 已投递子榜认可 nDCG@5 | 从方法的**完整 10 岗排名**中筛出相同一批已投递岗位，保留顺序，再评前 `min(5,子榜长度)`，以 S 作标签 | 已投递子榜至少有一个认可。另报无投递、已投递但无认可人数 |
| 全体人均 Top-5 联合正例数 | 每人统计前 5 中 `J=1` 的岗位数后取均值 | 全体 T，零正例名单计 0 |

例如，一名求职者只投递过完整榜上的第 2、6、8 位。评雇主侧时，按这个相对顺序评价三个岗位的认可记录。评最终榜的联合 Top-5 时，只有原榜第 2 位可能贡献联合正例。两项指标分别回答“已投递岗位中，获认可的岗位排在哪里”和“前五名中，哪些岗位曾被投递并获认可”。

报告每项指标的用户数和零正例人数。无可评价用户时记 NA 并写原因。回退用户按实际输出计分。以用户为重采样单位，配对 bootstrap 2,000 次给均值及差值的百分位 95% 区间。四个预登记差值均使用联合 nDCG@5，方向为 **B4−B1、T1−T0、F−T1、F−B4**。对用户差值做 10,000 次双侧配对符号置换（随机种子 `20261121`，p 值作加一修正），四个 p 值一起做 Holm 校正，显著性水平 0.05。W1、角色移除、两侧指标及 Optional 蒸馏作为解释性比较。保留负向效应、跨零区间和单侧损失。

## 5. 单卡工作量、时间预估与 Optional 蒸馏

正式规模固定为 C 128 人、T 256 人。Phase 3 只做硬件探测与耗时外推，使用独立 pilot 窗口，不读取测试标签。单卡执行时，32B 教师先生成示范并卸载，8B 学生再训练、重评。三条路线都从同一份主实验开始。

| 预估路线 | 计入工作量 |
|---|---|
| 主 pipeline | 原版 8B 共 14,336 窗，含 C 四角色 4,096、T 四角色 8,192、T 单评审 2,048，随后做 CPU 聚合与评测 |
| 主 pipeline + SFT | 主线＋32B 教师至多 2,048 个角色窗口＋8B 全参数监督微调 1 轮＋学生四角色重评 12,288 窗及 CPU 评测 |
| 主 pipeline + SFT + LoRA | 主线＋相同教师示范＋8B 通过共享 LoRA 适配器做监督微调 1 轮＋相同规模的学生重评 |

全参数 SFT 是硬件与工时对照。正式 Optional 实验采用第三行的 LoRA-SFT，结果标识沿用 `F-SFT`。三行分别估算独立路线的墙钟时间和 GPU 小时，[第 3 期](./phase3_pilot_budget.md)给出计时与外推方法。实际运行时，共享的主线结果、教师示范和 B1 缓存只记账一次。

**Optional 实验**在主矩阵完成后按以下顺序执行。

1. 在独立训练用户的固定 10 岗池内，每人随机无放回选至多两个不同的四岗组合，每窗恰好 `1 个 J 正例＋3 个 J 负例`。用固定种子抽样并打乱窗内位置。无合适窗口则记录并跳过。四个教师角色分别回答同一窗口。提示隐藏标签。
2. 本地 `Qwen/Qwen3-32B-AWQ` 生成示范。按角色独立保留格式有效且正例居首的输出，保存各角色尝试数和保留率。一个 `Qwen/Qwen3-8B` 学生共享一个角色条件 LoRA 适配器，使用监督微调，`rank=16`、`alpha=32`、学习率 `10⁻⁴`、1 轮。教师模型及论文做法见[模型卡](https://huggingface.co/Qwen/Qwen3-32B-AWQ)和[ConFit v3 §3.5、表 5–6](https://arxiv.org/pdf/2605.09760#page=4)。原论文使用 Claude Sonnet 4.5 作 SFT 教师，天池实验省略 SFT。32B→8B 为本项目设定。
3. 用学生输出在原 C 上重新拟合温度、可靠度和相关权重，在同一 T 上比较 F-SFT 与 F。记录实际新增 GPU 小时和中断阶段。未选做时登记“未运行”及原因。

## 6. 运行验收与证据

- **输入和配置。** 保存原始文件哈希、清洗计数、用户分组、各区块名单、起始岗位列表、模型 revision、提示词版本、输入输出 token 上限、生成参数、软件版本和硬件探测记录。同一次比较固定预处理、截断顺序和推理配置。
- **逐窗有效性。** 保存用户、角色、轮次、窗口起点、四岗输入顺序、输出排列、逐岗概率、解析状态及耗时。检查四个编号无重无漏，所需概率均为有限且位于 `[0,1]` 的数值。失败至多重试一次，再失败则将该查询的该角色标记为缺失，保留原始记录。
- **回退。** B1 失败则回退 BM25。多角色方法有效票少于两份时回退 BM25。PL 求解失败时记录收敛状态并回退 BM25。F 在可信排名回退时沿用该回退。若可信排名可用而任一侧预测缺失，则整份名单回退 T1。记录每种原因和用户数。
- **结果证据。** 保存校准折及样本外预测、6 对相关、权重、逐方法全序、逐人指标、配对差值、GPU 耗时账本和 Optional 状态。每个已填写的结果行关联本次运行的证据路径。验收依据为协议执行与记录完整性，效应方向由数据决定。按[结果矩阵](./acceptance_result_matrix.md)填写。
