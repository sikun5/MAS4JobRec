# 第 2 期｜数据清洗、用户划分与固定候选池

[主入口与数据口径](./experimental_setting.md) · 输入是本地三张 AliTianChi 表，可与[第 1 期](./phase1_model_prep.md)并行。可先在本地 CPU 生成产物，待远端目录就绪后传入并复核哈希，再交接给[第 3 期](./phase3_pilot_budget.md)。

## 1. 实验目标

为每位求职者生成一份可重放的 10 岗名单。分别交付推理输入、校准标签、封存测试标签和独立蒸馏训练区块，使后续方法可以在相同名单上配对比较。

## 2. 实验内容

1. 校验三份原始文件的 SHA-256，按主入口 §2.1 解析和连接。补齐 35 条末尾空经历，隔离 1 条异常 JD，同人同岗的三个标记逐列取最大值。保留浏览或投递过的岗位，包含唯一的 `010` 人岗对。
2. 依 §2.2 生成 BM25 起始榜。用全体有效 JD 统计 IDF，仅在个人触达池内取前 10，同分按 `jd_no` 升序。记录每人有序岗位 ID 和名单哈希。池内缺少正例的用户保留到评测分母统计。
3. 按种子 `20261121` 和规范化简历哈希去重分组。沿用已验收的 `data/splits.json` 中 `standard` 成员（16 pilot、128 C、256 T、最多 256 名独立蒸馏训练用户），直接复用名单及哈希。
4. 为模型生成盲评输入与临时岗位编号，隐藏三项行为、交互次数、原始 ID、标签及 BM25 分数。标签文件单独存放，保留 `D=delivered`、`S=satisfied`、`J=D×S` 和已投递掩码。数据构建程序可处理原始表，选榜、评审和硬件探测程序不接收测试标签。

**交接产物**为 `data/audit.json`、`data/splits.json`、`data/lists.jsonl`、`data/inputs.jsonl`、`labels/` 下按区块存放的标签。记录跨区块岗位重叠，保存各清单哈希。

## 3. 验收且可推进标准

- [x] 原始规模为 4,500 人、269,534 岗、700,938 行行为。关联后 648,171 行，合并后 473,032 对，触达 129,756 对，分组前至少有 10 岗的用户为 3,392 名。
- [x] 每个查询恰有 10 个不同岗位，两次从相同输入构造的起始名单一致。全部区块可从清单恢复，同人及同简历组跨区块重叠为 0。
- [x] 抽检盲评输入与标签文件的字段边界，验证 `D=0` 时 `J=0`、雇主判断为未知。测试标签可独立封存。

数据审计和第 1 期都通过后，将 16 人 pilot 名单交给第 3 期。计数不符时定位到解析、连接或合并步骤，重新生成依赖的名单并更新哈希。
